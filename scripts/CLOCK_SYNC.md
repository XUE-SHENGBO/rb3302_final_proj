# start1.sh 启动前自动向电脑校时

指定电脑：`192.168.50.92`。电脑运行用户级只读时间接口
`http://192.168.50.92:8765/time`，机器人每次新启动start1.sh时先请求该接口，
获得sudo权限后、实际采样之前完成密码验证，再选三次请求中往返最短的一次设置时间，
最后重新请求检查偏差。验证通过才启动ROS硬件。
TCP建连在计时采样之前完成，避免无线连接握手延迟影响校时估算。

这属于启动前一次性校准，不是持续NTP服务；不改变电脑时钟。检测到驱动、EKF、
AMCL、导航或任务进程仍在运行时拒绝校时。请按任务→导航→硬件的顺序停止旧进程，
再运行start1.sh。已有tmux会话仅重新连接，不会对运行中的机器人跳变校时。

## 电脑侧

本机已经安装并启用`rb3302-pc-time.service`用户服务，登录后自动运行，
仅绑定`192.168.50.92:8765`，提供时间JSON，不提供文件目录。

```bash
systemctl --user status rb3302-pc-time.service
systemctl --user restart rb3302-pc-time.service
journalctl --user -u rb3302-pc-time.service -n 20
```

单元模板在本目录`rb3302-pc-time.service`。工作区移动后需修改ExecStart，
电脑IP变更后需修改服务的--bind和start1.sh的默认地址，然后重载用户服务。
仅在本机登录会话内启用；没有开启系统级linger，服务不自动修改防火墙。
本次部署中用户已手动为机器人放行入站时间端口：

```bash
sudo ufw allow from 192.168.50.6 to any port 8765 proto tcp
```

## 机器人侧

正常执行原来的`./start1.sh`即可。需要sudo时在终端按提示输入；请求失败或校时
验证不通过会退出，避免继续用错误时间启动ROS。

只查看时间差，不改时间也不启动ROS：

```bash
python3 scripts/sync_pc_clock.py --host 192.168.50.92 --check
```

地址和端口可以显式覆盖：

```bash
RB3302_PC_TIME_HOST=192.168.50.92 RB3302_PC_TIME_PORT=8765 ./start1.sh
```

电脑必须连接机器人所在网络，并运行上述服务。机器人没有自动安装NTP软件、
没有配置免密码sudo，也没有绕过运行中校时限制。
